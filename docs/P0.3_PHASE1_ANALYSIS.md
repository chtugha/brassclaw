**Date**: 2026-06-19  
**Status**: Investigation Complete

---

## Executive Summary

The approval infrastructure is **already well-designed and implemented** in the engine. The gate system provides a complete framework for tool execution approval. P0.3 needs to:

1. **NOT** build a new approval system
2. **USE** the existing gate system properly
3. **Implement** a real `GateController` to replace `CancellingGateController`
4. **Integrate** the gate system with the scheduler's tool execution

## Existing Infrastructure

### 1. Gate System (`crates/brassclaw_engine/src/gate/`)

#### Core Components

**`GateDecision` Enum**:
```rust
pub enum GateDecision {
    Allow,                              // Execution proceeds
    Pause { reason, resume_kind },      // Wait for user input
    Deny { reason },                    // Block execution
}
```

**`ResumeKind` Enum**:
```rust
pub enum ResumeKind {
    Approval { allow_always: bool },    // User approval required
    Authentication { ... },              // Credential required
    External { callback_id },            // External system response
}
```

**`GateResolution` Enum**:
```rust
pub enum GateResolution {
    Approved { always: bool },          // User approved
    Denied { reason },                  // User denied
    CredentialProvided { token },       // Credential provided
    Cancelled,                          // Gate cancelled
    ExternalCallback { payload },       // External response
}
```

#### Gate Controller Trait

```rust
#[async_trait]
pub trait GateController: Send + Sync {
    /// Pause execution until user resolves the gate
    async fn pause(&self, request: GatePauseRequest) -> GateResolution;
    
    /// Cancel all paused gates for a thread
    async fn cancel_thread(&self, thread_id: ThreadId) {}
}
```

**`GatePauseRequest`**:
```rust
pub struct GatePauseRequest {
    pub thread_id: ThreadId,
    pub user_id: String,
    pub gate_name: String,
    pub action_name: String,
    pub call_id: String,
    pub parameters: serde_json::Value,
    pub resume_kind: ResumeKind,
    pub conversation_id: Option<ConversationId>,
}
```

#### Current Stub: `CancellingGateController`

```rust
pub struct CancellingGateController;

impl GateController for CancellingGateController {
    async fn pause(&self, _request: GatePauseRequest) -> GateResolution {
        GateResolution::Cancelled  // Always cancels
    }
}
```

**Usage**: Returns `Cancelled` for all pause requests, effectively denying all approval gates.

### 2. Gate Pipeline (`gate/pipeline.rs`)

**Purpose**: Evaluates multiple gates in priority order

```rust
pub struct GatePipeline {
    gates: Vec<Arc<dyn ExecutionGate>>,
}

impl GatePipeline {
    pub async fn evaluate(&self, ctx: &GateContext<'_>) -> GateDecision {
        for gate in &self.gates {
            match gate.evaluate(ctx).await {
                GateDecision::Allow => continue,
                decision @ (GateDecision::Pause { .. } | GateDecision::Deny { .. }) => {
                    return decision;  // First pause/deny wins
                }
            }
        }
        GateDecision::Allow
    }
}
```

**Key Features**:
- Gates sorted by priority (lower = earlier)
- First `Pause` or `Deny` stops evaluation
- All `Allow` = execution proceeds

### 3. Tool Tier Classification (`gate/tool_tier.rs`)

**Purpose**: Classify tools by privilege level

```rust
pub enum ToolTier {
    ReadOnly,        // No side effects
    Stateful,        // Local state changes
    Privileged,      // Write ops, external effects
    Administrative,  // System-level, never autonomous
}
```

**Classification Rules**:
1. In `AUTONOMOUS_TOOL_DENYLIST` → `Administrative`
2. `requires_approval: true` → `Privileged`
3. Only `ReadLocal`/`Compute` effects → `ReadOnly`
4. Everything else → `Stateful`

**Autonomous Denylist**:
- `routine_create`, `routine_update`, `routine_delete`, `routine_fire`
- `event_emit`, `create_job`, `job_prompt`
- `restart`, `tool_install`, `tool_auth`, `tool_remove`, `tool_upgrade`
- `skill_install`, `skill_remove`
- `secret_list`, `secret_delete`

### 4. Execution Mode (`gate/mod.rs`)

```rust
pub enum ExecutionMode {
    Interactive,              // User can approve
    InteractiveAutoApprove,   // Auto-approve unless Always-gated
    Autonomous,               // No user, lease-based

}
```

**NOT NEEDED**: The gate system is already complete. We just need to implement a real controller.

**Required**: `ApprovalGateController` that:
- Stores pending approval requests
- Notifies user via channels
- Waits for user response
- Returns appropriate `GateResolution`

**Required**:

**Required**: In-memory or database storage for:
- Pending approval requests

### 4. Notification System

**Required**: Send approval requests to user via:
- Signal

## Architecture Decision

### Option A: Implement Full Approval System (Original P0.3 Plan)
- Build approval storage
- Build notification system
- Build approval UI/commands
- Implement timeout handling
- **Effort**: 5-7 days

### Option B: Simplified Stub with Real Structure (Recommended)
- Implement `ApprovalGateController` that auto-approves everything
- Add logging for approval requests
- Prepare structure for future real implementation
- **Effort**: 1-2 days
- **Benefit**: Unblocks tool execution, provides clear path for future work

### Option C: Minimal Integration (Fastest)
- Keep `CancellingGateController` but make it configurable
- Add flag to auto-approve instead of cancel
- **Effort**: 0.5 days
- **Drawback**: Doesn't prepare for real approval flow

## Recommendation

**Implement Option B**: Simplified stub with real structure

### Rationale

1. **P0.2 is complete** - Tool execution works with stub lease
2. **Gate system is complete** - No need to build approval infrastructure
3. **Unblock development** - Allow tool execution to proceed
4. **Prepare for future** - Structure in place for real approval
5. **Incremental approach** - Can add real approval later without refactoring

### Implementation Plan

1. **Create `AutoApprovingGateController`**:
   ```rust
   pub struct AutoApprovingGateController {
       // Optional: track requests for logging/debugging
       pending_requests: Arc<RwLock<HashMap<String, GatePauseRequest>>>,
   }
   
   impl GateController for AutoApprovingGateController {
       async fn pause(&self, request: GatePauseRequest) -> GateResolution {
           tracing::info!(
               thread_id = %request.thread_id,
               action = %request.action_name,
               call_id = %request.call_id,
               "Auto-approving tool execution (P0.3 stub)"
           );
           
           // Store request for debugging
           self.pending_requests.write().await.insert(
               request.call_id.clone(),
               request,
           );
           
           // Auto-approve
           GateResolution::Approved { always: false }
       }
   }
   ```

2. **Integrate with Scheduler**:
   ```rust
   // In create_thread_execution_context()
   let gate_controller = Arc::new(AutoApprovingGateController::new());
   
   ThreadExecutionContext {
       // ... other fields ...
       gate_controller,
       call_approval_granted: false,
   }
   ```

3. **Add Configuration**:
   ```rust
   // Allow switching between auto-approve and cancel
   pub enum GateMode {
       AutoApprove,  // P0.3 default
       Cancel,       // P0.2 behavior
       Real,         // Future: real approval flow
   }
   ```

4. **Document Future Work**:
   - Add TODO comments for real approval implementation
   - Document notification system requirements
   - Document approval storage requirements
