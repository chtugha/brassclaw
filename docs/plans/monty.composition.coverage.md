# monty.composition — component coverage findings

Source audit: **2026-10-09**. This checks every one of the **118 PythonCode entries and 94 Skill companions** originally listed in monty.composition. It examines checked-in seeds and concrete planned usages; it does not query an installed database, run programs or establish activation. Names/reference matches were checked against source bodies and contract differences.

**Result:** 43 partial overlap, 48 no successor found, 8 existing code reuse, 9 planned replacement, 10 same original design. Nine planned replacements belong to validator_v3. Eight additional redundant bodies can reuse already-seeded general executors; those executors precede the specialized bodies, so this is existing-code consolidation, not evidence of later seeding. No listed body has a fully qualified later packaged drop-in replacement.

“Partial overlap” keeps the unique usage/contract work, while sharing the existing primitive or code where compatible. “Same original design” means a plan documents the very component being audited, not a replacement. “No successor found” is bounded to this checkout and reviewed plans, not a claim about installed overrides. A planned successor remains implementation work. Broader v3 architecture or an existing Rust Tool alone never proves that a replacement PythonCode component exists.

Inspection covered the three seeders, current global bootstrap/catalogue/root, component stores and proposal/Q1 consumers; the four component guides; validator_v3, simplified_v3 and its implementation plan; prefix plans; Zencoder and Skill-migration plans; Phase-P/doc-sync plans and actual component_db/memory/filesystem/grep handlers. Generated prefix exports, copied documentation, tests and superseded Action designs were not counted as new components.
