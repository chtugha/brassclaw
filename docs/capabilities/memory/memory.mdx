---
title: Persistent Memory
description: Your agent's durable, searchable long-term memory system
---

The LLM context window is temporary — everything in it disappears when the
conversation ends. The memory system is persistent: documents written to memory
survive indefinitely and are retrievable via hybrid search from any session.

The orchestrator uses memory tools through matched Recipes in the same way as
any other Tool. In Tier-2 (no-match free-form) turns, the LLM can call memory
tools directly. In either case, writes are subject to the prompt-safety
write policy before persistence.

---

## Workspace structure

The workspace uses a filesystem-like path hierarchy. Documents live at paths
you define:

| Example path | Use case |
|-------------|----------|
| `context/vision.md` | Project goals and direction |
| `context/architecture.md` | System design decisions |
| `daily/2024-01-15.md` | Daily notes and logs |
| `daily/standup.md` | Latest standup draft |
| `projects/brassclaw/notes.md` | Project-specific notes |
| `inbox/task-20240115.md` | Incoming tasks |
| `processed/task-20240115.md` | Processed and archived tasks |
| `ops/incidents/2024-01-15.md` | Incident records |

Paths are arbitrary strings. Use whatever structure makes sense for your
workflow. The `memory_tree` tool shows all paths as a directory tree.

---

## Memory tools

| Tool | Description |
|------|-------------|
| `memory_search` | Hybrid FTS + vector search. Returns ranked results. |
| `memory_write` | Write a document to a path. Creates or overwrites. |
| `memory_read` | Read a specific document by exact path. |
| `memory_tree` | List all paths in the workspace as a tree. |

These are class-0 Rust primitives registered through `builtin_bootstrap.rs`,
each backed by a ToolSkill, PythonCode, Skill, and Recipe in the standard v3
component stack. They are invoked through matched Recipes when a user message
triggers a memory-related workflow.

---

## Protected memory paths

Certain memory paths are **prompt-protected** — writes to them pass through
the prompt-safety write policy before persistence:

```
SOUL.md         AGENTS.md       USER.md         IDENTITY.md
SYSTEM.md       MEMORY.md       TOOLS.md        HEARTBEAT.md
BOOTSTRAP.md    context/assistant-directives.md  context/profile.json
```

These paths can be read and written with the same memory tools as any other
document. The safety policy validates their content before each write to
prevent prompt-injection attacks via workspace documents.

---

## Search and retrieval

BrassClaw uses **hybrid search** combining full-text search (FTS) and vector
similarity when pgvector is installed:

```
Keyword matches (FTS)  +  semantic similarity (pgvector)
         └──── Reciprocal Rank Fusion (RRF) ranking ────┘
```

`memory_search` returns ranked results from this combined index. For larger
workspaces, vector search provides semantic retrieval beyond keyword matching.

---

## Proactive memory use

The orchestrator searches memory as part of matched Recipes when a user asks
about prior work, past decisions, or previously stored information. If you
believe the agent has missed something:

```
Search memory for notes about the authentication refactor
```

or

```
memory_read path="context/architecture.md"
```

Significant task outputs should be written to memory so they are available in
future sessions:

```
memory_write path="projects/my-project/decisions/2024-11-03.md"
```
