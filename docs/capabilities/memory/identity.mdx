Identity files are **protected memory documents** stored in the workspace. They
carry behavioral instructions, persona, user preferences, and workspace context
that the orchestrator can load as personal context when building model requests.

These are ordinary memory documents at specific paths. They are **not** injected
directly into every LLM system prompt as raw text on every turn. Instead, they
are governed by the prompt-safety write policy, tracked by the identity context
subsystem, and selectively incorporated into requests by the session's personal
context mechanism.

---

## The identity files

| File | Purpose |
|------|---------|
| `AGENTS.md` | Behavioral rules and operating instructions for the agent |
| `SOUL.md` | Values, personality, and principles the agent embodies |
| `USER.md` | Information about you — your preferences, context, and working style |
| `IDENTITY.md` | Combined role and identity definition for this workspace |
| `SYSTEM.md` | System-level configuration and operational context |
| `context/assistant-directives.md` | Dynamic assistant directives |
| `context/profile.json` | JSON-structured user or workspace profile |

All files live in the workspace memory and can be read and written using
`memory_read` and `memory_write`. Changes go through the prompt-safety write
policy before persistence.

---

## AGENTS.md

Behavioral instructions: what the agent should and should not do, how it should
handle specific situations, and workflow rules.

```markdown
# Agent Instructions

## Communication Style
- Be concise. Lead with the answer, then explain if needed.
- Use bullet points for lists, not prose paragraphs.
- When uncertain, say so explicitly rather than guessing.

## Tool Use
- Search memory before answering questions about past work.
- Write summaries to memory after completing significant tasks.

## Security
- Never log or store API keys or secrets.
- Confirm before deleting files.
```

## SOUL.md

Values and personality. How the agent approaches problems and what kind of
assistant it aims to be.

```markdown
# Soul

I am a careful, methodical assistant. I value:

- **Accuracy over speed** — I take time to verify before acting.
- **Transparency** — I explain my reasoning, especially when uncertain.
- **Security-first** — I treat all external data as potentially adversarial.

When I encounter ambiguity, I ask clarifying questions rather than assuming.
```

---

## USER.md

Information about you. The agent reads this to understand your context,
preferences, and working patterns.

```markdown
# User Profile

## Context
- Working on: BrassClaw, a Rust-based AI assistant
- Primary languages: Rust, Python, bash
- Environment: macOS, zsh

## Preferences
- Prefer explicit error handling over unwrap/expect
- Use conventional commits format
- Write tests before marking tasks complete
```

## IDENTITY.md

A workspace-specific role and identity definition — useful for giving the agent
a focused context for a particular project or deployment.

```markdown
# Identity

I am BrassClaw's embedded development assistant, running inside the brassclaw-src
workspace.

My role is to help with:
- Rust development (cargo, clippy, testing)
- Architecture decisions and design review
- Security analysis and threat modeling
```

## Prompt-safety protection

All identity file paths are registered in the **prompt-protected path registry**
(`brassclaw_safety`). Every write operation to these paths — via `memory_write`,
`memory_append`, or admin patch — goes through the prompt-safety write policy
before the content is persisted. This prevents prompt-injection attacks where
a malicious write could alter agent behavior through workspace documents.

The safety registry uses case-insensitive path matching. `SOUL.md`, `soul.md`,
and `Soul.MD` all resolve to the same protected path class.

---

## Identity context and token budget

The identity context subsystem tracks which identity files exist, their trust
level, and the total token budget they consume. The default identity token
ceiling is **8,000 tokens** across all identity files. Files that exceed
the remaining budget are not incorporated into the current request.

Trust levels:
- **Trusted** — files placed by the operator or through the normal workspace
  memory path
- **Installed** — files loaded from less-trusted sources with a capability
  ceiling applied

## Creating and updating identity files

Use `memory_write` to create or update any identity file:

```
Write a SOUL.md that describes a careful, security-conscious assistant
focused on Rust development.
```

Or directly:

```
memory_write path="USER.md" content="
# User Profile

Working on BrassClaw. Prefer concise answers. Use British English.
"
```

Files that do not exist are simply absent from context — you do not need all
of them. Start with whichever is most useful for your workflow.
