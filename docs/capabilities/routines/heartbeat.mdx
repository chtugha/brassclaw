The heartbeat system gives BrassClaw proactive agency between conversations.
On each configured tick it reads `HEARTBEAT.md` from the workspace memory and
submits its contents as an action to the orchestrator — without you having to
explicitly ask.

`HEARTBEAT.md` is one of the **protected memory paths** in BrassClaw's prompt
safety registry. Changes to it are tracked, and it can be read and written
using the memory tools (`memory_read`, `memory_write`).

---

## How it works

On each heartbeat tick:

1. The trigger poller detects that the heartbeat interval has elapsed.
2. A trigger event is submitted through the trusted trigger ingress.
3. The orchestrator receives it as an admitted task and executes the
   heartbeat Recipe, which reads `HEARTBEAT.md` and runs its instructions
   as an action.
4. If the run produces output that warrants attention, a notification is
   sent to the configured channel.
5. The run is recorded in `routine_runs` with a status of `ok`, `attention`,
   or `failed`.

If `HEARTBEAT.md` does not exist or is empty, the tick is a no-op.

---

## HEARTBEAT.md format

Write `HEARTBEAT.md` as a checklist of tasks. The action runs these
instructions on each tick:

```markdown
# Heartbeat Checklist

## Daily Tasks
- [ ] Check memory at daily/ for yesterday's notes. If missing, remind the user.
- [ ] Search memory for any items tagged as "follow-up" or "urgent" and list them.
- [ ] Read ops/stuck-jobs.md if it exists and summarize any unresolved incidents.

## Weekly Tasks (run only on Mondays)
- [ ] Summarize the week's daily notes into a weekly summary at weekly/<date>.md
- [ ] Check for any routines that haven't run in the past 7 days and flag them.

## Always
- [ ] If any of the above produce findings, write a summary to memory at heartbeat/latest.md
- [ ] Only notify the user if there are actionable items — do not send empty pings.
```

---

## Notification behavior

After each tick, if the run produces output with status `attention`, the
heartbeat system sends a notification to the configured channel. Runs with
status `ok` and no significant findings do not notify — heartbeat is designed
to be quiet unless it has something useful to say.

---

## Configuration

Heartbeat interval and notification target are configured via routine settings:

| Setting | Default | Description |
|---------|---------|-------------|
| Heartbeat interval | 1800 s (30 min) | Seconds between ticks |
| Notify channel | `tui` | Channel for attention notifications |
| Notify user | `default` | User ID to notify |

To adjust the interval, update the heartbeat routine via `routine_create` or
Settings → Routines. Increasing the interval reduces LLM API usage and is
recommended if the heartbeat action is token-intensive.

---

## Writing HEARTBEAT.md

Ask the agent to create or update the heartbeat checklist:

```
Write HEARTBEAT.md with tasks to check my inbox/ folder every 30 minutes
and summarize any new items.
```

Or use the memory tool directly:

```
memory_write path="HEARTBEAT.md" content="
# Heartbeat

- [ ] List all memory documents in inbox/ — if any exist, summarize and move to processed/
- [ ] Check if daily/<today>.md exists — if not, create a daily entry template
- [ ] Only notify if inbox/ had items or daily notes were missing
"
```

## Heartbeat vs Cron routines

| Feature | Heartbeat | Cron Routine |
|---------|-----------|--------------|
| Configuration | Single `HEARTBEAT.md` file | Per-routine record in `routines` table |
| Schedule | Fixed global interval | Custom per-routine cron expression |
| Scope | Single checklist action | Multiple independent routines |
| Complexity | Simple — edit one file | Flexible — manage multiple routines |

Use heartbeat for a unified set of periodic checks. Use cron routines when
you need different schedules for different tasks, or when tasks should track
independent run histories.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Heartbeat not firing" icon="clock">
    - Confirm `HEARTBEAT.md` exists in the workspace root
      (`memory_read path="HEARTBEAT.md"`)
    - Check startup logs for the trigger poller startup message
    - Verify the heartbeat routine is enabled in Settings → Routines
  </Accordion>

  <Accordion title="Getting too many notifications" icon="bell">
    - Update `HEARTBEAT.md` with an explicit condition:
      "only notify if there are actionable items"
    - Increase the heartbeat interval in the routine settings
    - Make checklist items more specific to reduce over-reporting
  </Accordion>

  <Accordion title="Heartbeat run consuming too many tokens" icon="coins">
    - Simplify `HEARTBEAT.md` — fewer checklist items mean fewer steps
    - Increase the interval to reduce frequency
    - Add constraints like "use at most 5 tool calls per run" in the checklist
  </Accordion>
</AccordionGroup>
