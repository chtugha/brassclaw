## Exact inspected source

actual retained parser observations. The root and every transitive dependency
must be the exact inspected class-22 revisions with effect-free preloads.

## Declaration: `pure-component-approval/1`

`PureComponentApprovalDeclaration::from_json` accepts exactly these fields:

| Field | Rule |
| --- | --- |
| `format` | Exactly `pure-component-approval/1`. |
| `approval_id` | Canonical non-nil UUID of the immutable declaration. |
| `root` | Exact `{uuid,class_code,version,checksum}` reference, present in `components`. |
| `components` | Nonempty complete selected closure, one exact revision per UUID. Every class is 22. |
| `validation_mode` | `authored` or `system_seed`; a declaration is not provenance. |
| `q1_ref` | Canonical non-nil UUID of required successful trusted Q1 evidence. |
| `q2_ref` | Distinct canonical non-nil human evidence UUID for authored work; null for shipped seeds. |
| `behavioral_refs` | Nonempty distinct canonical non-nil evidence UUIDs; cannot reuse Q1/Q2. |

References have exactly four fields. Versions are positive integers representable
by the database's signed 64-bit revision identity; booleans/floats are invalid.
Checksums are 64 lowercase hexadecimal SHA-256 characters covering the actual
immutable revision documents, including source/interfaces/dependencies. Reject
unknown/duplicate JSON keys, duplicate components, missing/mismatched root and
incorrect evidence shapes under the caller's finite data limits.

`require_selected_snapshot` compares against one complete exact rooted snapshot.
It rejects changed source, interface, version or dependency selection. It neither
reads evidence nor proves purity or approval. Existing Skill-association and
association-approval formats are unchanged; no zero-Tool Skill is created.
