## Confirmed gaps and implementation consequences

1. **UUID-only pure lookup is not exact approval.** The loader ignores the selected
   root version, checksum, approval identity and dependency closure. The declaration
   already has `require_selected_snapshot`, but a source search finds callers only
   in its contract tests. B2-03 must connect the exact checker to B1's trusted proof
   owner. Do not merely add a UUID to another allow-set.
2. **Preparation and later verification disagree.** Authored preparation extends
   `independently_qualified` with the DB loader, while the common selected-program
   verifier reconstructs only canonical shipped generation coverage. In addition,
   the final catalogue-wide `covered` set is not extended from general pure
   approvals. Adding one query cannot establish complete publication/dispatch.
   These are source-confirmed missing checks/support, not a demonstrated successful
   end-to-end exploit or proof that other fail-closed gates have disappeared.
3. **No exact pure approval pins are serialized.** The /1 recipe selection carries
   usage association pins only. Reconstruction cannot recover which general pure
   approval was selected by reading latest. B2-02 must define separate exact pins
   and versioned readers before B2-05 enables their publication.
4. **Preparation storage is strict at two layers.** Both the validator envelope
   and its nested recipe selection have explicit supported fields/format. Updating
   only the engine serializer would break private restoration. Functional A
   Skill/code subjects need the existing successor subject work; do not make /1
   silently accept a changed/contextual partner.
5. **Pure writer trust is still B1 work.** The public store adapter delegates
   arbitrary declaration JSON to a writer that checks evidence `succeeded` flags.
   It does not establish kind, exact subject/closure, authenticated human decision
   or genuine shipped provenance. The B2 reader must not treat all existing V200
   rows as trusted simply because their columns/JSON parse correctly.
6. **V201 does not enforce the claimed cross-row equality.** Its final CHECK only
   repeats a non-nil component test; separate foreign keys cannot bind a link's
   component/version to both its submission and approval root. The application
   writer compares submission fields, then checks only approval existence. B1-06
   must repair the actual connected relationship with a successor migration and
   direct-SQL negative cases; do not edit the already-shipped migration in place.
7. **Historical format compatibility and unfinished recovery are separate.** Old
   /1 policy absence, archived class-50 data and unsupported crash restoration
   cannot be relabeled as successor support. B2-09 retains old bytes/pins and
   requires explicit compatible upgrade or reconciled draining. New format errors
   never authorize another VM, Rust loop, rematching or Tier-2 fallback.
