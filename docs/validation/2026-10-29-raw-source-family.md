# Raw secret sources on the retained family — 29 October 2026

The retained source preparation now captures each declared raw handle's actual
authenticated generation or absence alongside account sources on the existing
task family. Complete raw declaration groups stay with their original native
capability. No account usage is manufactured for a raw declaration. Repeated
uses share immutable source metadata; children retain their actual parent's
family through the existing verified carrier.

The same invocation-owned object supplies raw resolution and synchronous
source-use checks. It verifies exact target scope, capability/handle, original
generation and weak task-host lifetime/fence. Missing captured material cannot
adopt a later value. Resolution performs no fresh SecretStore lookup or lease.
Metadata is host-only; it is not secret material, permission or a checkpoint.

The actual bound obligation preflight no longer reads current raw metadata.
Injection reuses the existing conditional lease/consume/staging function, with
checks before issuance, after issuance and after consumption. An unused fenced
lease is revoked; late consumed material is dropped without staging. Existing
abort/cleanup owns partial handoffs. Missing original secret ports stay missing.
The separately identified unbound legacy path is not claimed as migrated.

`BoundCredentialServices` extends the earlier named account-only bundle with the
raw port. The existing native binding and policy cache now cover every declared
credential source. Native identity, actual handler, live kernel policy, captured
account resolver/guard, staging services and governor remain intact. No workflow,
queue, task registry, Tool identity, VM or provider selection is introduced.

## Open boundaries

Native builtin credential declarations remain empty. This source/consumer
infrastructure does not fabricate a native GSuite identity, activate an ordinary
raw/account workflow, or migrate every unbound legacy consumer. Qualify actual
extension/native artifacts, ToolSkill bindings and their real consumers in K3
step4. GSuite's global resolver/stager and Rust refresh/retry sequencing cannot
be made v3 compliant by registration alone.

Own-flow adoption, original refresh-input progression, native Auth-wait production,
aggregate readiness for multiple credentials, complete final-use/UI behavior,
technical-policy coordination and durable recovery remain with their existing
owners. This is not full K3, Exact, Prefix, platform, release or deployment
acceptance. Reuse the [original-flow generation foundation](2026-10-29-original-auth-flow-source.md)
and [Exact's retained Recipe/profile contract](2026-10-29-exact-recipe-prefix-selection.md).
