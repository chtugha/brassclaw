## Behavior and architecture

Early component boot retains drafts only. Normal PostgreSQL/skills-db Monty
startup requires positive existing installation-inventory observation, then
qualifies the eight shipped structural checking PythonCode exports and their
small receipt comparator before returning public readiness. Exact packaged
factories select immutable revisions rather than mutable allocation heads.

Each checking function has a fixed Recipe fixture workflow, typed constant/result
bindings, independently literal expectations and actual contained native Monty
execution through the existing admitted runner and packaged global root. The
receipt helper is itself behaviorally qualified first. It compares complete rule
objects and projects the existing `validator-step-results/1` format. All declared
union slots have explicit `consumer_default` bindings to nullable defaults;
selected slots require real non-null rule objects, unused null slots are allowed,
and unselected non-null results fail. Strict schemas reject unknown fields.
Matrix sizes differ between class suites and helper self-oracles.

Expected negative Python stops require original typed input fingerprints, exact
retained invocation/source and native Python-failure classification plus the
specific final diagnostic. Worker death, cancellation and arbitrary errors cannot
satisfy them. Native failure closure has a separate projection and never creates
a successful model-free quiescence capability.

Private typed evidence binds exact definitions, recipes, fixture selections,
worker/application/global-root bytes and relevant implementation owners. A
reservation winner records one execution request. Original executor/preparation,
admission, observations and terminal custody are retained. Complete originals
are checked before current budgets/policy; incomplete originals remain unresolved
and are never rerun. Full original readback precedes the existing `/1` writer.
Approval existence alone is insufficient. Authored heads, active overrides, old
pins and historical records remain intact. Uncertain writer COMMIT connections
are discarded through the existing evidence I/O custody owner.

The existing RetainedInputs owner now exposes its full input-edge fingerprint
verification for reuse by both validator-subject and E-01 readers. Immutable
contract schema metadata uses the existing `REVISION_LIMITS`; captured task
limits still govern source inspection and actual execution. No new primitive,
ordinary VM, queue, approval format, source substitution or retry path is added.

Qualification is only the helpers' own shipped behavior. It does not approve
candidate components, complete candidate-class Q1, general Pure publication,
successor `/2`, the other 24 collector/aggregate/receipt roots or class workflow
activation. B2's qualified selector and historical-disposition integration remain
separate prerequisites. Genuine shipped S qualification adds no installed or
external human Q2. Adjacent L013 placeholder qualification remains outside E-01.
