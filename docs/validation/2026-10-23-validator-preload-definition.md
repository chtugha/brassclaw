## Implemented boundary

`validator_components::preload_definition_draft` declares one class-22 export,
`check_preload_definition(inputs)`, with its private identifier helper. Complete
recursive typed inputs describe the preload declaration and actual native
`SourceStructure`, including scopes/calls, host-call sites and nullable preload
facts. Unknown fields, missing required inputs and invalid/null values are
rejected by the existing contract binder. Missing declarations and unsupported
definition shapes produce explicit negative rule results. Optional default-export
absence is distinct from a required input; it follows the native declaration
reader. The factory validates its own input/result contracts before retention.

The PythonCode compares actual signatures, public/private implementation symbols,
constants and imports against declarations. It diagnoses conflicting/invalid
names, mapping signatures, duplicate constants/imports and unknown defaults.
The rule reads data and returns the existing `{rule_id,ok,errors}` contract;
it never executes candidate source, writes evidence or chooses a workflow.
Dependency resolution, direct invocation/input contracts, forbidden source
operations, transitive Tool calls, isolation/behavior and provenance need their
separate mandatory checks. In particular, a genuine Tool-using definition can
pass this rule without being qualified as pure or approved for dispatch.

Installation uses the existing immutable revision store and namespace
`validator:preload-definition`. Repeated retention finds the exact package bytes;
it preserves older revisions and authored successors. It creates no legacy
validator replacement, confidence stamp, review evidence, approval or active
catalogue. Original legacy validator UUIDs still require the planned inventory
and class-route migration. This draft is not an external maintainer/Q2 gate.
