# Native prefix acceptance and complete-request callers — 29 October 2026

The native OpenAI Chat Completions **text** path now binds actual Pair/Profile/
Generation acceptance to the ordinary Kohai/Sempai request boundary and the global
post-turn Sempai caller. Tests use real PostgreSQL, the actual registry SDK,
the bounded tokenizer/template worker and global Monty. Their controlled HTTP

## Retention and acceptance

V182–V185 extend the existing owners rather than adding a second settings or
approval registry. Source-only compiler packages retain their exact original
bytes and source-only status. A separate `brassclaw-prefix-target-generation/1`
contains the original source package and exactly the finished `prefix.utf8` and
`model_input_binding.json`. Import/read checks their hashes, original source row,
Pair/Profile proposals, mapping and immutable tokenizer/default-template assets.
Source-only packages cannot become serving generations by changing a label.

`prefix_acceptances.rs` prepares native evidence, seals the reviewed identity,
records exact scoped Pair/Profile/Generation approvals and resolves the retained
graph. Operator content/default-contract review remains explicit; neither a
model-supplied count nor an `approved: true` request qualifies a candidate.
Unchanged accepted parents may be reused without rewriting their evidence.
Generation-specific leading token-ID fingerprints belong to the generation,
not a shared Pair contract. Approval does not activate: a separate CAS updates
the existing target binding. Idempotent retries retain the original result.

The existing authenticated operator facade exposes review, approve and activate
under `/api/webchat/v2/prefix-model-designs/acceptance/`. Request bodies do not
provide a trusted actor or native measurement. The APIs and native backing owner
are connected; this receipt does not claim completed frontend controls or that
ordinary Generate already constructs these target envelopes.

## Actual SDK serialization determines the stable boundary

The real SDK combines system messages into one preamble. A previously proposed
fixed prefix ended with a system closing delimiter. Once dynamic system
instructions were joined, that delimiter no longer followed the fixed reference.
An independent Jinja diagnostic against the actual captured SDK body confirmed
the discrepancy. Guard weakening and server-template changes are unnecessary:
the accepted per-model design uses the valid open reference boundary and counts
the closing frame in the dynamic suffix. The entire reference remains present.
This fixture's boundary is not a universal template recommendation.

The new `brassclaw_llm::request_qualification` captures the actual registry SDK
serialization without submitting HTTP. Its measurement callback deliberately
rejects, and its dispatch policy also denies submission. It never fabricates a
successful measure or model answer. The corpus covers single/joined system
messages, history and, when declared, tools/history and tool continuations.
Existing protocol/resource bounds and provider request timeouts apply.

Acceptance runs both authored worked cases and this native corpus through the
same real bounded tokenizer/default-template worker. The complete encoding must
retain the exact leading prefix bytes and stable leading token IDs. The rejected
closed-frame candidate is covered before approval. Pair construction `/2` makes
wire mapping, supported modes, normalization and positive request-output default
explicit; the latter is a request default, not another hard-limit setting.

For each actual send, `ContainedFinalRequestMeasurer` renders/tokenizes the final
SDK body once, verifies retained artifacts/selection/mode and checks exact leading
bytes and token-ID fingerprint. Canonical prefix, dynamic-prompt, output and total
context constraints apply even when discretionary token budgets are off. Live
policy is checked again at the submission fence. Missing context, unsupported
mode/transport, changed assets or mismatched binding cannot select an unguarded
fallback. Unmeasured callers retain the older tightening fence; selected native
callers can evaluate tightened-but-fitting caps with actual current counts.

## Ordinary and post-turn callers

Task admission captures the provider snapshot, actor and exact active target
qualification once in `brassclaw-task-provider-binding/2`. Children retain their
original task-family selection. Later role/target edits do not replace the
selected generation. Typed `ProviderRole` selects Kohai's base-prompt or Sempai's
reviewer prefix; a missing required binding fails the actual model call, while
model-free deterministic tasks remain possible.

The shared gateway adds the reference exactly once at the final boundary, after
the dynamic prompt preparation. It uses the selected original default-template
contract to produce the already-qualified model-facing prefix; it neither
double-frames it nor runs a second compiler. Both completion and Tools paths use
the same guard on the actual serialized request. Legacy inline/context-bundle
prefix insertion is suppressed on that native path.

The global post-turn reviewer uses its own captured Sempai binding through the
same owner. Its original model selection and original HTTP response bytes are
retained immutably. A retry of failed persistence does not repeat inference.
Ordinary admission and review admission have explicit distinct native custody;
absence of one is not permission to impersonate the other. Existing effect
accounting distinguishes proven local rejection from an unresolved dispatched
request. Recipes/PythonCode retain review/proposal workflow decisions.
