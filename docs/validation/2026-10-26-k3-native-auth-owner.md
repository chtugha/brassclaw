## Change and actual owner

The factory already constructs a native PostgreSQL secret store. It now retains
that same concrete Arc whenever PostgreSQL is enabled and supplies it to
PgAuthProductServices, independently of RootLLM. The native owner can therefore
participate in the existing secret transaction ports without a downcast, another
store or an unsupported generic default. The runtime's existing public LLM field
keeps its original feature boundary. Actual provider/callback fixtures retain the
same native inner store and their real HostOAuth observer.

The PostgreSQL-only profile exposed connected preexisting feature errors. The
pure class-label helper now belongs to the actual PG backend, its service test
import is test-only, and WebUI wiring/fallback exports match their real RootLLM
consumers. Metadata and ticket-management members are compiled only with their
actual consumers; real test producers stay available. Two completely unused
private DTO fields and their dead-code allowances are removed. Generation storage
reads the request ID from its actual scope ticket. Shared PG primitives remain
available without RootLLM; no feature is forced on and no warning is suppressed.
Actual Skill classifications 1–3 now display Skill, preserving numeric codes and
removing the false DomainSkill/ScaffoldSkill hierarchy. This is header metadata,
not model-specific prefix rendering, design selection or serving implementation.

Secrets AGENTS and the storage contract remove obsolete libSQL runtime/parity
claims while retaining historical migration support. Both are release-indexed
inputs and were included in current native/global qualification.
