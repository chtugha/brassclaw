# Retained global worker hosting — 2026-10-23

**Scoped native acceptance passed** for this hosting repair on the final source
below, including the separate Monty caller workspace. This is not general
pure approval, class Q1, durable interpreter/run/attempt/settlement evidence,
automatic crash recovery or full platform/release/installed acceptance.

Ordinary startup reuses the `PackagedExecutableImage` already captured and
protocol/parser-probed by Source-Inspection under the selected settings. The
catalogue retains that exact object and derives all preparation paths from its
private copy. `GlobalMontyOwner::start` takes the retained image, not an arbitrary
installation path, and carries it into actual service spawning. No second image
capture, process manager, per-chat VM or alternate workflow is added. Existing
closed qualification copies remain their owners' exact byte-identity checks;
this repair does not change Prefix workflows, approval formats or generations.

The owner and existing singleton/quarantine registry retain that same image.
Abandoned startup, a dropped error receipt or unknown worker/service settlement
cannot discard the artifact while the singleton remains quarantined. Only actual
quiescence permits the existing release path. Known shutdown/invalid actor
handling and ownership fencing retain their existing semantics. The interpreter
image limit is the existing acknowledged native-artifact policy; no new cap,
periodic pressure measurement or operator approval is introduced.

The real native source-inspection regression compares Arc identity among the
source backend, catalogue and ordinary owner and checks the actual worker checksum.
It still checks live resource/settings revisions, current Tool policy, registered
native identity and nonexecution of inspected source. A separate real owner test
deletes only its temporary installation projection before starting from the retained
copy, observes a live worker/root and singleton exclusion, and requires actual
shutdown/release before cleanup. The existing quarantine test additionally checks
that the worker image survives dropped receipts and is removed after known release.

All 16 affected standalone fixture callers use the same retained-image constructor
through an explicit test-only capture helper and existing finite preparation
defaults. Their tests are isolated caller evidence, not application bootstrap
qualification. The original root task/state/Tool/Recipe selection is unchanged.
