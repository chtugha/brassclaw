## Implemented behavior

Operator `POST` and read-only `GET` share `/api/webchat/v2/prefix-model-designs/proposals/{specification}/{proposal}/jobs/{job}`. The body-free submission captures the existing complete source-owned case packet through the previously qualified private ResultOnly path. It does not create a queue, execution loop, database table or token setting. The authenticated instance-operator route set, descriptor policy and actual router agree.

One shared status projection handles Profile and Pair targets. The discriminated `target_kind` retains the existing profile JSON fields for Profile jobs; Pair jobs contain their exact specification/proposal references and no synthetic profile or revision. The runtime's source namespace, immutable target and actual admission/run/actor correlation must agree. Reading does not recollect sources, complete a task or replay native operations.

Each retained proposal in Model Designs now exposes **Compare construction cases**. Browser storage retains only its original correlation ID. A lost response can reconnect to that same job; opening a remembered job and Refresh only read. A new ID requires an explicit action after a terminal, durably settled result. Older reads/errors are fenced, duplicate clicks coalesce, and mismatched response targets are rejected. Comparison verdicts require the exact completed, settled receipt and are visibly separate from design acceptance, provider-wire/cache compatibility and activation. The panel adds no polling interval or copied model limit.
