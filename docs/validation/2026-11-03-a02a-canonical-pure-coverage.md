## Contract and reused owners

Preparation and retained selected-program verification now call one
`verify_independent_execution_coverage` in `authored_monty_catalogue`.
It uses the unchanged `BootstrapGenerationApproval` owner: exact original
pre-pin candidate checksum, durable qualification verification in the caller's
coherent transaction, then byte equality of the full actual approval-pinned
selection. Only that verified selection supplies its unbound occurrence map,
keyed by step ID and exact component revision. Missing, extra or changed
occurrences fail before execution. A separate rooted graph projection supplies
dependency coverage; those UUIDs never authorize other occurrences.

The old `load_independently_qualified` had only one caller. It and its UUID-only
admission branch are removed. Approval rows, public exact-original resolution,
internal writer and historical evidence remain intact. Bound usage checks,
native implementation verification and live kernel policy are unchanged.
No new migration, retained format, interface digest, producer, VM or fallback.

Mandatory architecture reading and the complete first caller/contract inventory
were handed off before authorization at
`/private/tmp/brassclaw-a02-first-handoff-20261103.md`; its source manifest is
`/private/tmp/brassclaw-a02-inspection-20261103.json`. Architecture consequences:
one UUID per component step; effect-free preload and pinned exports; separate
usage, graph and independent occurrence approval; own A review versus exact S
qualification; original selections across waits/children; errors never No-Match.
General positive Pure needs the separately assigned B1-APP/B2-SEL contract.
No B-01 queue/submission/approval-production source or V206 was changed.

## Reader scope

- Prepare/reload: `prepare_with_policy` calls the shared checker after actual
  native inspection and association pinning; restore regenerates identical bytes.
- Fresh/retained capture: `verify_source_selection` delegates to
  `verify_retained_selection`, which calls `verify_selected_approvals`.
- Child: `monty_child_tasks::capture_child_task` verifies the original retained
  view through that same checker before passive binding and explicit selection.
- MCP: command qualification uses `verify_selected_approvals`; original command
  recompilation still retains exact existing association pins and compares full
  selection checksums. No new command is advertised by this package.
- Private Validator and Prefix jobs retain their existing operation-specific
  owners/scopes. Their immutable bytes and admission contracts are unchanged.

Source inventory found no other supported general independent Pure `/1` profile.

final graph coverage and retained verification. Its earlier explicit rejection
