## Implemented path

`validator_source_inventory.rs` defines the one-Tool usage with recursive string-
map input, exact string output, stop-only single-attempt failure and preload
contracts. The canonical command captures `entries_json` verbatim. A separate
pure PythonCode decoder turns the complete JSON list of `[ID, source]` pairs
into typed data, rejecting duplicate/empty IDs and malformed/nonstring entries
before any Tool call. Escaped equivalent IDs cannot overwrite earlier entries.
The Recipe binds/invokes the native inventory usage and then the existing reply
usage, publishing the exact native report. Private validators reuse only the
typed inventory usage. Source text remains data and is never executed.

The installation owner resolves the actual registered Tool, verifies its native
artifact and retains both source profiles' exact drafts through the existing
immutable revision store. Both usages share one compatible ToolSkill. Existing
operator Recipe successors, original selected bytes and current Tool blocks
survive repeated retention. No approval, confidence, active catalogue pointer or
review evidence is written. The existing dispatcher/kernel/PG journal supplies
execution and live policy; the development observer adds no product workflow loop.
Disposable utility protocol remains 5 and global protocol remains 20.
