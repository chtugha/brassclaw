# Original Tool-account source capture and use — 29 October 2026

The existing catalogue preparation now retains original account selections and
actual encrypted generations before binding consumer runtimes. It reads exact
registered native declarations and captures each complete ProductAuth-account
usage once. Missing selection/account/material, fenced preparation and uncaptured
closed-review contexts remain distinct. A later global choice or newly available
secret cannot silently fill captured absence.

The real native child operation carries its actual parent's immutable family
before the first admission await. It does not reconstruct source ownership from
IDs or reread today's selection. The original logical account scope remains
separate from the child's exact native invocation and host/claim scope.

SelectedTools binds the captured services only after retaining its original
native intent and answer handle. It preserves native identity and the same live
kernel policy. Binding failure is received/acknowledged as that original result,
without leaving custody open or replaying the Tool. Model and transcript ports
retain their existing independent source owners.

Explicit native account binding requires a `RuntimeCredentialUseGuard` from the
same invocation object as the account resolver. It has no default-allow v3
implementation or Tool permission. It checks original scope, InvocationId, host
lifetime/fence, complete usage and selected generation. The kernel checks it
before conditional issuance, after issuance and after consumption. A fence
revokes an unused owned lease; late consumed material is dropped rather than
staged. Cleanup errors remain failures with redacted diagnostics. Readonly source
lookups can end on cancellation without waiting for their backend; mutating
lease/consume results remain owned and are never discarded as presumed no-effect.

Current account eligibility and issuer/store deadlines remain independently
checked. The source-use guard supplies no new account, lineage, grant or policy
override. Existing unbound legacy service contracts remain separate migration
work. A named BoundAccountServices struct replaces the rejected complex tuple;
no lint is suppressed.
