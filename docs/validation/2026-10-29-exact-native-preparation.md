# Exact K3-2: native preparation and bootstrap infrastructure — 29 October 2026

This scoped implementation follows the [document successor](2026-10-29-exact-k3-2-doc-contract.md).
It supplies reusable bootstrap components, extends the existing final counter,
and moves existing native task selection ahead of runtime binding. The
[receipt](2026-10-29-exact-native-preparation.json) binds sources, retained
executables, worker, commands and results. **Exact I1–I7 remain incomplete.**

## Delivered behavior

The fixed B1/B2 prompts and response schema are packaged with exact integrity
hashes. The exported Rust constructors now compile in the actual Skills module
and produce existing typed class-22 drafts. Their Python exports prepare exact
prompts and check answer structure and captured scalar evidence without an LLM.
The native strict JSON reader remains mandatory before these pure stages;
the legacy JSON Tool's last-wins parse is insufficient. These drafts have no
active seed, model dispatch, provenance importer or design-approval writer.

The existing `ContainedFinalRequestMeasurer` now accepts a distinct immutable
workflow encoding selection without invented generation/acceptance identifiers.
It reuses the same worker, provider-wire mapping, tokenizer, complete-request
accounting and final guard. A workflow's physical prefix span is zero; all fixed
instructions, history and Tools still count toward the prompt. Existing
acceptance verifiers reject workflow selection by default. There is no production
workflow verifier or intentional prefix-free dispatch yet.

The existing global task factory retains its original ordinary catalogue,
internal job or native child preparation before model/configuration awaits.
It captures and persists the original model selection once, then constructs
runtimes from that same retained preparation. Catalogue selection, native child
provenance, run/attempt identities, parent dependencies and the original admission
remain with their existing owners. There is no second queue, model selector or
Tool-source registry. `CapturedMontyCatalogue` and `CapturedChildBindings` expose
the actual inspected programs for the next native consumer; `prepare` replaces
the old capture-and-bind method. Internal prefix jobs defer their existing
runtime constructor through the same invocation's once-bound carrier.

Passive construction permits a cancelled child to reach the existing global
service's acknowledgement. Actual dispatch still checks cancellation and live
kernel policy. Missing model capture differs from an explicitly captured absent
selection. A captured binding cannot be rebound to a newer catalogue or another
host/admission.

The source/build window is returned to the Root/Auth owner after this terminal
handoff. That owner consumes the captured source before late runtime binding
for original Tool credentials; it does not put credentials into the model-prefix
namespace or add another factory capture path. Old receipts remain historical.
