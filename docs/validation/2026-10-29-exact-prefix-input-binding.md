# Exact K3-2: typed prefix input contract — 29 October 2026

This scoped successor consumes the Root/Auth [nineteen-path handoff](2026-10-29-tool-source-capture-and-use.md)
and extends the existing model capability, response custodian and final gateway.
The [machine receipt](2026-10-29-exact-prefix-input-binding.json) binds ten changed
source paths, before/after hashes, retained executables, source manifests and logs.
**This does not complete Exact I2 or activate prefix-free workflows.**

## Delivered behavior

One neutral `RecipePrefixSelection` distinguishes Default, Selected and
PrefixFreeWorkflow. The resolved prefix keeps actual content and Inline versus
FinalBoundary insertion separate from intentional absence. Its constructors
reject empty references, whitespace-only present content and contradictory
present/free combinations. Historical inline construction preserves its original
scope; no generation or acceptance IDs were invented.

The original native model response record projects a typed
`LoopModelInputReference` through its existing custodian. The final gateway
compares both semantic choice and reference before provider submission. A matching
string with a different choice fails. Missing native evidence cannot authorize
prefix omission. An explicit matching free binding preserves fixed instructions,
history, the real final guard and the captured positive output reservation while
inserting no generated system prefix. Present bindings retain the existing single
insertion. Explicit request output limits remain explicit.

The current PostgreSQL `/1` writer remains qualified for present prefixes only
and rejects Free before model submission. A structural constructor alone supplies
no workflow approval, native evidence writer or dispatch permission. Existing
pure String readers reject absence instead of returning an empty prefix or
silently using the catalogue. Ordinary completed-turn review still follows its
original present-prefix contract.

No credential binding, current policy, model route, original task family,
TaskProviderSelection/2 format, Tool invocation identity or factory capture path
was replaced. No component, Recipe, workflow, endpoint or serving pointer was
activated.

## Remaining integration

Exact I2 still needs supported reviewed Recipe/variant authoring metadata,
qualified native workflow capture, versioned persisted selection, exact Selected
resolution, noncircular bootstrap preflight and recursive child/review propagation.
Root capture currently still reads prefix bindings; the qualified free workflow
must avoid that lookup. The new type and gateway barrier are prerequisites, not
those integrations. Discovery/import, design acceptance, WebUI, integrated Q1/Q2
lifecycle and reference-safe collection retain their open owners.

The source audit also corrected Exact §5.2.2(6): current wire/provider/loop bodies
do not contain `prefix_reference`. The native owner binds that immutable DB column
to the occurrence, while the payload checksum covers payload bytes. New selection
metadata must be consistently versioned and verified in the same owner; an
unnecessary SDK wire-protocol change does not follow from this requirement.
Old payloads, references and checksums remain original.

After this terminal package, Source/Cargo is explicitly returned to Root/Auth.
Exact freezes shared executable inputs until a new handoff. The existing
[native preparation receipt](2026-10-29-exact-native-preparation.md) and Root/Auth
acceptance retain their separate scopes and historical bytes.
