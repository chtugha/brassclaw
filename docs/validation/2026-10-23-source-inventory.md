## Actual implementation and boundaries

[The interface contract](../reborn/source-inventory-inspection.md) describes the
exact profiles/result and resource/error behavior. `source_inventory.rs` compiles
and inspects complete named sources within the existing utility worker. One
process/deadline/allocator covers the complete map, with shared source, AST and
output accounting. Bounded parent preflight precedes owned copying; reply checks
retain exact IDs/hashes and reject incomplete or changed inventories. A counted
full wire reply catches escaped/frame overhead before publication. Source strings
never become an invocation of their contents.

HostRuntime adds this profile to the existing registered capability/schema and
backend, without a new Tool or dispatch bypass. Composition reuses one captured
retained image/settings revision and the same report/usage/error owner for both
profiles. Current kernel Tool policy covers both. Request copying remains inside
the existing native wall-time measurement boundary. No periodic pressure sampling,
new resource cap, extra global VM or Rust business validator is introduced.

The disposable utility wire advances from 4 to 5; the global service stays on 20.
All affected callers use the paired codec. Compiler `syntax`/`unsupported`/`import`
are mechanical profile facts, not semantic verdicts; resource, transport/native
and traversal failures remain whole-operation errors. The existing compiler
nesting guard remains an open cap/profile issue in [the resource audit](../runtime-limits-audit.md).
