HOW TO CREATE A SEMPAI PREFIX — EXACT PROMPT

BEGIN PROMPT
From this BrassClaw repository, prepare a Sempai reviewer reference with
scripts/prefix/sempai-compiler.py. Use a separate compiler cache and a pinned local
Ornith tokenizer/config snapshot. Collect the eleven allowlisted source documents,
including the full recipe.md, skills.md, tools.md, toolskills.md, AGENTS.md,
CLAUDE.md, simplified_v3.md, validation queue, Sempai proposal transport/persona
and scripts/prefix/sempai-authoring-reference.md. Do not fetch HA sources.
Preserve all originals. For the reviewed 100000-token selection, set
SEMPAI_REFERENCE_POLICY to scripts/prefix/sempai-reference-policy.json. It keeps
the four full binding guides, full reviewer procedure and proposal transport,
plus explicitly reviewed source units from the other documents. Reject source
hash/unit drift or missing mandatory contracts; do not greedily shorten them.

The reference must teach provider-specific Kohai prompt diagnosis and reusable
component/Recipe proposals, exact typed IBS authoring, associations, failure/retry
contracts, Q1, behavioral validation and human Q2. Keep current implementation,
binding targets and historical persona examples distinct. Preserve every required
source unit and literal evidence. Missing provider metadata, UUIDs, API support,
approval and observed test results stay unknown. Do not include private conversations
or secrets in the reusable prefix. Source collection is not component approval.

Set SEMPAI_SOURCE_ROOT to the checkout or installed source-package directory,
CODING_DISTILL_CACHE to an independent evidence directory and ORNITH_MODEL_CONFIG
to a local snapshot's config.json. Run collect, distill and doctor, then compile
with --mode context --offline --context-tokens 100000. Use existing dependencies;
never alter vLLM services, Compose, model environments or templates. If the complete
required reference cannot fit, report Capacity blocked with the measured size and
preserve the originals. Do not reduce coverage or claim a prefix was deployed.

Report source_manifest.json and, if compilation succeeds, the immutable generation
paths, actual tokens and unverified cache assumptions. Deployment/DB seeding and
base-plus-Sempai consumer wiring are separate steps in docs/plans/prefix_v3_upgrade.md.
END PROMPT

COPY/PASTE TERMINAL EXAMPLES — LINUX AND MACOS

Run in a full BrassClaw checkout or a source package preserving these relative
paths. This does not connect to or modify the inference server. Replace the Python
and model-config paths with EXISTING compiler resources before pasting commands.
The interpreter needs openai, httpx, transformers and the pinned fast tokenizer's
dependencies; compiling needs tokenizer/config files, not model weights.

cd /path/to/brassclaw
export PREFIX_PYTHON=/path/to/existing/compiler-environment/bin/python
export ORNITH_MODEL_CONFIG=/path/to/pinned/model/config.json
export SEMPAI_SOURCE_ROOT="$PWD"
export CODING_DISTILL_CACHE="$PWD/sempai-evidence"
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export TRIAGE_MODE=local
export SEMPAI_REFERENCE_POLICY="$PWD/scripts/prefix/sempai-reference-policy.json"

"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode plan
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode collect
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode distill
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode doctor

For a reproducible rebuild, pin the generated inventory before recollecting:

cp "$CODING_DISTILL_CACHE/raw/source_manifest.json" "$CODING_DISTILL_CACHE/pinned-source-manifest.json"
export SEMPAI_SOURCE_MANIFEST="$CODING_DISTILL_CACHE/pinned-source-manifest.json"

"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode context --offline --context-tokens 100000

Successful output lives under "$CODING_DISTILL_CACHE/generations/<generation>/":
context_100k.md, vllm_prefix_template.jinja, evidence_cards.jsonl, prefix_manifest.json.
Reviewed builds also include source_selection_policy.json. The manifest pins its
SHA256, accounts for omitted units and distinguishes selected reference coverage
from the complete preserved originals. Unset SEMPAI_REFERENCE_POLICY to request
the original full-document model-visible policy (currently exceeds Ornith capacity).
The current pointer publishes a local compiler bundle; it does not activate a server.
Full raw documents remain under raw/documents/<sha256>.txt even on capacity failure.
The 100000 target is an explicit preview setting, not BrassClaw's disabled global
token budget. The copied model/cache adapter currently targets Ornith's measured
hybrid geometry; offline results do not prove runtime/native/external cache reuse.

The --mode run entry point uses the shared citation validator for factual reference
questions only. It requires a separately deployed verified prefix and the active
server template; it does NOT implement SempaiReviewOutcome, submit component drafts,
perform Q1/Q2 or activate anything. Production Sempai uses the existing interceptor,
trusted typed review packet, DB provider catalogue and proposal/validation paths.

LIVE REVIEWER TESTS — AFTER DEPLOYMENT AND HEALTH VERIFICATION

Run from Linux or macOS with an existing Python 3. These requests send ordinary
messages and the reviewer output persona, never a client copy of the reference.
The server must already be injecting the verified Sempai generation. Choose a NEW
output directory so prior test evidence cannot be overwritten.

python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 \
  --output ./sempai-evaluation-new-run

The evaluator exports raw provider responses and unapproved component designs.
It does not submit to PostgreSQL, run production Q1, approve human Q2 or activate
components. Check generated code behavior separately and retain runtime gaps.
The current Sempai sink supports classes 21/22 only and discards v3 Recipe
step_descriptions/variants/dependency_registry. Offline v3 designs must not be
submitted through that lossy sink. Generated PythonCode using inputs needs the
selected runner's typed-input contract before production execution.

The measured 2026-10-06 deployment and candidate results are recorded in
scripts/prefix/sempai-evaluation-20261006/README.md. Ordinary output was frequently
Markdown-fenced JSON; --json-mode requests the tested provider JSON response mode.
Valid JSON alone is insufficient: duplicate, malformed or semantically wrong
components must still be rejected. Run check_sempai_candidates.py on Linux for
the bounded independent behavior probes; these checks are not production Q1/Q2.
