HOW TO CREATE A SEMPAI PREFIX — EXACT PROMPT

BEGIN PROMPT
From this BrassClaw repository, prepare a Sempai reviewer reference with
scripts/prefix/sempai-compiler.py. Use a separate compiler cache and a pinned local
Ornith tokenizer/config snapshot. Collect the current allowlisted BrassClaw documents,
including the four complete binding guides, reviewer procedure, proposal transport
and complete verified worked examples. Preserve the complete pinned official Monty
v1.0.0 documentation package in scripts/prefix/monty-reference/v1.0.0 (commit
85c5d1f6bef038405cfc40a4eed94806e303567e) and the separate BrassClaw compatibility
guide. Do not fetch HA sources or substitute changing upstream main-branch pages.
Require the teaching JSON manifest and real Linux verification receipt; preserve
both sidecars with the originals. A stale or missing receipt blocks compilation.
Use scripts/prefix/sempai-reference-policy-preload-v22.json for the reviewed whole-unit
selection. The policy pins this source snapshot, not a permanent license to accept
future source drift. If another author changes components or guides, preserve
that work, capture a new coherent source package, review the changed selection
and rerun affected teaching verification before compiling again. Keep old
bundles/receipts; never edit compiler integrity checks or overwrite published
generations to make a digest mismatch disappear. Preserve all raw originals; reject changed hashes, missing
mandatory contracts or corrupted upstream artifacts before invalidating the cache.
Compile to 114688 tokens with PREFIX_WORKSPACE_RESERVE_TOKENS=16384. The current
rendered reference uses about 114000 tokens; never truncate guides to make it fit.

The reference must teach provider-specific Kohai prompt diagnosis and reusable
component/Recipe proposals, exact typed IBS authoring, associations, failure/retry
contracts, Q1, behavioral validation and human Q2. Keep current implementation,
binding targets and historical persona examples distinct. Preserve every required
source unit and literal evidence. Missing provider metadata, UUIDs, API support,
approval and observed test results stay unknown. Do not include private conversations
or secrets in the reusable prefix. Source collection is not component approval.

Set SEMPAI_SOURCE_ROOT to the checkout or installed source-package directory,
CODING_DISTILL_CACHE to an independent evidence directory and ORNITH_MODEL_CONFIG
to a local snapshot's config.json. Run collect, distill and doctor, then compile
with --mode context --offline --context-tokens 114688. Use existing dependencies;
never alter vLLM services, Compose, model environments or templates. If the complete
required reference cannot fit, report Capacity blocked with the measured size and
preserve the originals. Do not reduce coverage or claim a prefix was deployed.

Report source_manifest.json and, if compilation succeeds, the immutable generation
paths, actual tokens and unverified cache assumptions. Deployment/DB seeding and
base-plus-Sempai consumer wiring are separate steps in docs/plans/prefix_v3_upgrade.md.
END PROMPT

COPY/PASTE TERMINAL EXAMPLES — LINUX AND MACOS

Run in a full BrassClaw checkout or a source package preserving these relative
paths. This does not connect to or modify the inference server. Replace the Python
and model-config paths with EXISTING compiler resources before pasting commands.
The interpreter needs openai, httpx, transformers and the pinned fast tokenizer's
dependencies; compiling needs tokenizer/config files, not model weights.

cd /path/to/brassclaw
export PREFIX_PYTHON=/path/to/existing/compiler-environment/bin/python
export ORNITH_MODEL_CONFIG=/path/to/pinned/model/config.json
export TOKENIZER_MODEL=/path/to/pinned/model
export PREFIX_WORKSPACE_RESERVE_TOKENS=16384
export SEMPAI_SOURCE_ROOT="$PWD"
export CODING_DISTILL_CACHE="$PWD/sempai-evidence"
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
export TRIAGE_MODE=local
export SEMPAI_REFERENCE_POLICY="$PWD/scripts/prefix/sempai-reference-policy-preload-v22.json"

"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode plan
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode collect
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode distill
"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode doctor

For a reproducible rebuild, pin the generated inventory before recollecting:

cp "$CODING_DISTILL_CACHE/raw/source_manifest.json" "$CODING_DISTILL_CACHE/pinned-source-manifest.json"
export SEMPAI_SOURCE_MANIFEST="$CODING_DISTILL_CACHE/pinned-source-manifest.json"

"$PREFIX_PYTHON" scripts/prefix/sempai-compiler.py --mode context --offline --context-tokens 114688

Successful output lives under "$CODING_DISTILL_CACHE/generations/<generation>/":
context_100k.md, vllm_prefix_template.jinja, evidence_cards.jsonl, prefix_manifest.json,
source_manifest.json and teaching/<sha256>.json verification sidecars.
Reviewed builds also include source_selection_policy.json. The manifest pins its
SHA256, accounts for omitted units and distinguishes selected reference coverage
from the complete preserved originals. Unset SEMPAI_REFERENCE_POLICY to request
the original full-document model-visible policy (currently exceeds Ornith capacity).
The current pointer publishes a local compiler bundle; it does not activate a server.
Full raw documents remain under raw/documents/<sha256>.txt even on capacity failure.
The 114688 target is an explicit preview setting, not BrassClaw's disabled global
token budget. The copied model/cache adapter currently targets Ornith's measured
hybrid geometry; offline results do not prove runtime/native/external cache reuse.

The --mode run entry point uses the shared citation validator for factual reference
questions only. It requires a separately deployed verified prefix and the active
server template; it does NOT implement SempaiReviewOutcome, submit component drafts,
perform Q1/Q2 or activate anything. Production Sempai uses the existing interceptor,
trusted typed review packet, DB provider catalogue and proposal/validation paths.

LIVE REVIEWER TESTS — AFTER DEPLOYMENT AND HEALTH VERIFICATION

Run from Linux or macOS with an existing Python 3. These requests send ordinary
messages and the reviewer output persona, never a client copy of the reference.
The server must already be injecting the verified Sempai generation. Choose a NEW
output directory so prior test evidence cannot be overwritten.

python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 \
  --output ./sempai-evaluation-new-run \
  --schema-mode

The evaluator exports raw provider responses and unapproved component designs.
It does not submit to PostgreSQL, run production Q1, approve human Q2 or activate
components. Check generated code behavior separately and retain runtime gaps.
The current Sempai sink supports classes 21/22 only and discards v3 Recipe
step_descriptions/variants/dependency_registry. Offline v3 designs must not be
submitted through that lossy sink. Generated PythonCode using inputs needs the
selected runner's typed-input contract before production execution.

The measured 2026-10-06 deployment and candidate results are recorded in
scripts/prefix/sempai-evaluation-20261006/README.md. Ordinary output was frequently
Markdown-fenced JSON; --json-mode requests the tested provider JSON response mode.
Valid JSON alone is insufficient: duplicate, malformed or semantically wrong
components must still be rejected. Run check_sempai_candidates.py on Linux for
the bounded independent behavior probes; these checks are not production Q1/Q2.

The evaluator includes six regression cases and six added variants: raw
scalar/list/boolean validators, an invoked helper, completed-effect preservation,
unknown provider facts and a specifically authorized prompt repair. Three further
confirmation cases cover enum matching, missing versus null and nested objects.
--schema-mode requests the exact supported reviewer envelope through provider
structured decoding; it does not establish correct code or approval. --json-mode
is the weaker JSON-object comparison. --thinking is a separate comparison option,
not a recommended default: observed complex drafts exhausted 8192 output tokens
while reconsidering serialization. Keep its raw failures if testing it. First-pass
runs must omit --repair-from; feedback repairs are separate evidence.
Add --preserve-message-count with --schema-mode to constrain the message-array
length to the supplied conversation. This constrains length, not roles or content;
the evaluator independently checks those. The v7/v8a comparisons use this option.

# Linux: run after the evaluator completes, using that same output directory.
python3 scripts/prefix/check_sempai_candidates.py ./sempai-evaluation-new-run

Complete verified examples remain in literal source blocks. Presence-aware and
parameterized helper examples are ordered nearest the task; a concise source-derived
contract checklist follows them at the reference boundary. Binding guides remain
complete. This placement is a measured candidate, not model training or a guarantee.
Refresh source-selection fingerprints explicitly after source changes; actual Linux
teaching verification must pass before collection. Preserve every generation and
failed model response.
See scripts/prefix/sempai-optimization-20261006/README.md for the later measured
optimization results and remaining limitations.

SEPARATE PROTOCOL EXPERIMENTS — NOT PREFIX-ONLY ACCURACY

--direct-contract places the trusted host's existing review instruction as plain
system text, while the original conversation remains packet data. No expected
outputs, test oracles or executable solutions are added. The default mode keeps
the original presentation for controlled prefix-only comparisons.

Optional --strict-drafts constrains the offline constructor field names/types and
unused compatibility arrays. --single-proposal adds an at-most-one draft limit ONLY
when that is the trusted current contract, as it is in this frozen suite. It does
not apply to live multi-component creation. --preserve-message-content is ONLY for an explicitly
read-only host review contract. It preserves the original input array; it does not
supply generated-code answers. Mark EVERY authorized edit case explicitly with
--editable-message-case. Production needs typed edit authorization; never infer
permission from an archived message or apply this test flag to all live turns.

Compact EBNF avoids arbitrary formatting whitespace outside JSON strings. String
contents (including spaces/tabs) remain exact. Export trusted response schemas on
the development machine, then compile with an EXISTING environment containing
XGrammar (the vLLM environment already has it). These commands install nothing,
start no engine and change no service. Choose fresh paths for every experiment.

# This concrete example uses the frozen development suite. Only prompt-00..05
# authorize edits; the other cases explicitly require unchanged messages.
python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 --output ./unused-schema-export \
  --cases-file scripts/prefix/sempai-accuracy-20261006/frozen-cases.json \
  --schema-mode --preserve-message-count --strict-drafts --single-proposal \
  --preserve-message-content \
  --editable-message-case prompt-00 --editable-message-case prompt-01 \
  --editable-message-case prompt-02 --editable-message-case prompt-03 \
  --editable-message-case prompt-04 --editable-message-case prompt-05 \
  --export-schemas ./sempai-host-schemas-new.json

# Run where XGrammar is ALREADY available; replace this interpreter path.
/path/to/existing/vllm-environment/bin/python \
  scripts/prefix/compile_sempai_grammars.py \
  --schemas ./sempai-host-schemas-new.json --output ./sempai-grammars-new

# Copy the fingerprinted grammar directory back if compilation was remote.
python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 --output ./sempai-protocol-new-run \
  --cases-file scripts/prefix/sempai-accuracy-20261006/frozen-cases.json \
  --schema-mode --preserve-message-count --strict-drafts --single-proposal \
  --preserve-message-content --compact-grammar-dir ./sempai-grammars-new \
  --editable-message-case prompt-00 --editable-message-case prompt-01 \
  --editable-message-case prompt-02 --editable-message-case prompt-03 \
  --editable-message-case prompt-04 --editable-message-case prompt-05 \
  --direct-contract

# Linux: validate every whole artifact against the same unchanged checks.
python3 scripts/prefix/check_sempai_candidates.py ./sempai-protocol-new-run

BOUNDED REPAIRS — NEVER MERGE INTO FIRST-PASS SCORES

After a completed run and Linux checking, prepare feedback from real failures.
It includes failed checks/counterexamples, not a synthesized replacement program.
Select only the reported rejected cases; keep all original responses and receipts.
For another round, use a NEW output and feedback file. No repair is approval.

python3 scripts/prefix/prepare_sempai_feedback.py ./sempai-protocol-new-run \
  --output ./sempai-feedback-round1.json

# Repeat --case for each rejected case named by the feedback helper. Use the
# SAME decoder/presentation flags as the originating experiment if applicable.
python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 --output ./sempai-repair-round1 \
  --cases-file scripts/prefix/sempai-accuracy-20261006/frozen-cases.json \
  --schema-mode --preserve-message-count \
  --repair-from ./sempai-protocol-new-run \
  --feedback ./sempai-feedback-round1.json --case CASE_ID_FROM_FEEDBACK

python3 scripts/prefix/check_sempai_candidates.py ./sempai-repair-round1

Report first-pass acceptance and acceptance after each bounded repair separately.
The evaluator retains its exact loaded source plus parent/failed-response/feedback
fingerprints. After Linux checking each round, produce a provenance-checked report:

python3 scripts/prefix/report_sempai_repairs.py \
  --first-pass ./sempai-protocol-new-run \
  --repair ./sempai-repair-round1 --max-repair-rounds 2 \
  --output ./sempai-bounded-acceptance-new.json

For a second round, repair ONLY remaining rejected cases using round 1 as the
parent, then repeat --repair ./sempai-repair-round2 in the reporter. Never overwrite
previous drafts/checks. The reporter rejects changed contracts, unpinned parent
evidence, an unrelated run or reprocessing an already accepted case.
A truncated or mismatching message is a rejection; do not normalize, salvage or
silently replace it after generation. Serving errors now retain HTTP bodies and
abort after three consecutive server errors; restore serving before measuring
accuracy. None of these experiment options is wired into production Sempai yet.

BOUNDED PLAN BEFORE DRAFT — SEPARATE TWO-CALL EXPERIMENT

--plan-first asks the model to construct a short branch/workflow/evidence plan
from the actual current contract, then write the complete candidate using that
unverified plan. Plans are not approvals or ground truth. The writer must check
against the original contract; the unchanged Linux validator checks the output.
No counterexamples or solutions are supplied during first-pass evaluation.
--single-layout is ONLY for an explicit offline one-description/one-variant
Recipe contract. It never selects UUID values, step count, order or effects.

Export the plan schema and compile it where XGrammar already exists:

python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 --output ./unused-plan-export \
  --export-plan-schema ./sempai-plan-schema-new.json

/path/to/existing/vllm-environment/bin/python \
  scripts/prefix/compile_sempai_grammars.py \
  --schemas ./sempai-plan-schema-new.json --output ./sempai-plan-grammar-new

When using --single-layout, also add that flag to the response-schema EXPORT
command above and compile that fresh response grammar. Different schemas require
different fingerprinted grammars; mismatches fail closed before inference.

HYBRID SHARED-ROOT PRIMING — SERIAL TESTS ONLY

Use an exported bundle matching the CURRENT server template. Choose a NEW cache
namespace per experiment and keep it unchanged for that entire run. Priming sends
short one-token requests, verifies automatic injection, native shared-root reuse
and the expected READY answer. Hit counts alone cannot detect a previously
corrupted state. It does not upload the reference again or change service settings.
Do not overlap other model tests or warm another namespace while a run is active;
GPU eviction and external restoration can invalidate the serving experiment.
The helper's request-local cache statistics are the acceptance evidence; instance
Prometheus counters can include other clients. A failed native-root check stops
accuracy measurement. This is not a fix for external recurrent-state persistence.

export SEMPAI_BUNDLE=/path/to/exported/immutable/generation
export SEMPAI_CACHE_NAMESPACE=sempai-serial-new-experiment

python3 scripts/prefix/prime_sempai_prefix.py \
  --server http://192.168.10.171:8000 --bundle "$SEMPAI_BUNDLE" \
  --cache-salt "$SEMPAI_CACHE_NAMESPACE" --output ./sempai-root-new.json

# Run ONLY after successful priming. This frozen suite explicitly requests one
# Recipe layout and authorizes prompt edits only in prompt-00 through prompt-05.
python3 scripts/prefix/evaluate_sempai_prefix.py \
  --server http://192.168.10.171:8000 --output ./sempai-planned-new-run \
  --cases-file scripts/prefix/sempai-accuracy-20261006/frozen-cases.json \
  --schema-mode --preserve-message-count --strict-drafts --single-proposal \
  --single-layout --preserve-message-content --direct-contract \
  --compact-grammar-dir ./sempai-grammars-new \
  --plan-first --plan-grammar-dir ./sempai-plan-grammar-new \
  --cache-salt "$SEMPAI_CACHE_NAMESPACE" \
  --editable-message-case prompt-00 --editable-message-case prompt-01 \
  --editable-message-case prompt-02 --editable-message-case prompt-03 \
  --editable-message-case prompt-04 --editable-message-case prompt-05

# Linux: all whole artifacts must pass; a plan or valid JSON is insufficient.
python3 scripts/prefix/check_sempai_candidates.py ./sempai-planned-new-run

Two calls increase latency. Compare accuracy and serving failures independently
of the original single-call client. Never label combined protocol gains as a
prefix-only result, or a finite development score as flawless general performance.

EXTERNAL HYBRID CACHE CORRECTNESS — CHECK BEFORE ACCURACY TUNING

cache_salt is a cache namespace, not an accuracy setting. Requests sharing a
prefix must share a stable namespace to reuse its cache. A new salt isolates a
new experiment; using a random salt on every call defeats reuse. For deployments,
version the namespace with the immutable bundle and compatible serving layout;
never share opaque recurrent pages across incompatible backends or block sizes.

On brassclaw, LMCache 0.5.5 was missing --separate-object-groups while vLLM used
Mamba/GDN align mode, block size 1056 and prefill batch size 8192. The installed
CLI supports that option. LMCache requires it to store recurrent checkpoints
independently of full-attention pages at these batch sizes. That required option is
/etc/systemd/system/lmcache.service.d/91-hybrid-object-groups.conf; the original
units and vLLM prefix override are retained. Both existing services were restarted
to register the changed layout and discard the old in-memory cache objects.
Do not apply this machine-specific helper to a different deployment blindly:
enable_lmcache_hybrid_groups.py deliberately checks the inspected configuration.
Separation alone FAILED the live restore check. A second issue was the installed
adapter's rank-five-only matching: vLLM's rank-four attention buffers stayed at
32-token physical pages instead of 1056-token logical pages. Upstream PR 4253
fixes that mapping. Its single adapter class and contiguity-helper import were
backported without upgrading packages; the exact original file is backed up at
/root/lmcache-4253-backport-20261007T082404Z/kv_cache_group_edits.original.py.
The guarded apply_lmcache_4253_backport.py and pinned source/diff are in this repo.
Do not equate merely installing the patch with a passed live restore check.
The preserved post-backport plain and structured checks both pass on actual
external restores; cache-fix-verification.json records their scope and hashes.
An LMCache package upgrade may overwrite this local backport. Recheck the adapter
fingerprint and rerun the live restore diagnostic after upgrading.

This diagnostic makes five SERIAL short requests in two namespaces. The second
namespace displaces the first from GPU memory. Its receipt must show zero native
hits and extra LMCache hits on the returning request; otherwise external restore
was not exercised. This temporarily displaces the current prefix cache, so run it
while inference is idle. It does not change service settings or execute Tools.

python3 scripts/prefix/diagnose_sempai_cache.py \
  --server http://192.168.10.171:8000 --bundle "$SEMPAI_BUNDLE" \
  --cache-salt sempai-cache-check-new --output ./cache-check-new.json

# Reuse these same namespaces to exercise constrained decoding after restoration.
python3 scripts/prefix/diagnose_sempai_cache.py \
  --server http://192.168.10.171:8000 --bundle "$SEMPAI_BUNDLE" \
  --cache-salt sempai-cache-check-new --structured \
  --output ./cache-check-structured-new.json

Read external_restore_check_passed in both receipts. These sentinel checks isolate
serving corruption; they do not establish Sempai accuracy or replace whole-draft
behavioral validation and Q1/Q2. See sempai-accuracy-20261007/README.md for evidence.
